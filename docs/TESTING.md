# 测试与验证

## 测试层次

| 层次 | 内容 | 可以证明 | 不能证明 |
|---|---|---|---|
| 静态检查 | 源文件、相对链接、包清单与敏感样式检查 | 已知可检测的发布问题未出现 | 没有任何隐私信息或法律问题 |
| 纯函数 | URL、输入、DWR 响应与请求体 | 合成输入下行为一致 | 平台接口仍沿用该协议 |
| 本地集成 | 模拟 CDP、CLI 参数与离线计划 | 超时、错误、确认边界可复现 | 已登录真实浏览器的行为 |
| 代理评估 | 按场景选择流程与证据表述 | 给定场景下的决策符合约束 | 所有未来对话均正确 |
| 真实平台 | 授权账号中读页/接口与人工核验 | 指定日期和条件下的观察 | 全平台、所有课程、后续学期通用 |

## 本地命令

在项目根目录、Node.js 22.15.0 或以上版本执行：

```sh
npm ci
npm run check
npm test
npm run test:coverage
npm pack --dry-run
```

测试使用 `node:test`，运行时无第三方依赖；传输采用合成对象，不打开网络套接字，也不接触课程网站或用户浏览器。`npm test` 通过 `scripts/run-tests.mjs` 为测试子进程设置项目 `.local/test-runs/` 下的独立临时目录并在结束后清理，不修改全局环境，避免依赖不可写的系统临时目录。受限环境若禁止子进程，应记录环境拒绝，不能把未执行记为通过。

`node scripts/selftest.mjs` 保留为历史兼容入口；完整测试以 `npm test` 为准。覆盖率辅助寻找遗漏，不以单个百分比替代失败路径与写入约束的验证。

`npm run check` 包含受控源文件清单、文档链接与已知个人数据模式等项目检查。它只是启发式检查，仍需人工审阅待发布目录与 Git 历史。`npm pack --dry-run` 展示将打入包的文件，没有发布行为；npm 日志应保存到个人缓存或 `.local/`，不要提交。

## 必要回归范围

- URL 只接受官方域名和受支持学习路径；拒绝伪造后缀、相似课程 ID、学期不匹配及多个未消歧候选。
- 非法选项、缺值、重复标志、无效 ID、空输入和损坏 JSON 离线失败。
- DWR 响应只解析数据，不执行代码；异常优先，正文中的单词不误判为异常；不把其他回调中的 ID 当成当前回复。
- 预览不连接浏览器；摘要绑定课程、学期、正文与规则证据；修改内容或缺少确认不能写入。
- 已有日志、未知话题归属、提交响应含糊时保留证据并停止；不自动重复提交。
- CDP 对超时、关闭、错误响应、上下文失效和无响应目标有明确失败；退出时回收连接与定时器。
- 考试状态无法确定时返回 UNKNOWN；视频输出不把 DOM 样式改称服务端逐项证明。

具体已实现用例以 `test/` 与 `npm test` 输出为准，本文描述验收范围，不宣称每个未来平台场景均已覆盖。

## 真实浏览器的隔离冒烟检查

`npm run test:browser -- --browser <Chrome可执行文件绝对路径>` 使用新建的临时数据目录和合成 `data:` 页面，覆盖真实 WebSocket 探活、并发 attach、执行与导航、错误响应、超时和取消。也可使用 `CHROME_BINARY` 环境变量指定可执行文件。脚本不会复用已登录资料，不连接课程平台，结束后关闭自己启动的浏览器并清理临时目录。

这是按需执行的检查；`npm test` 不启动浏览器。Chrome 必须能够在当前执行环境正常启动；受限执行沙箱可能阻止 Chrome 子进程，不能据此修改参数关闭 Chrome 自身沙箱。按宿主授权机制处理执行环境限制，无法运行时记录为未执行。

## CI 矩阵

源码中的 `.github/workflows/ci.yml` 当前按所有者要求只运行 Windows × Node.js 22.15.0 / 24，Linux 阶段暂缓。依次运行 `npm ci`、`npm run check`、`npm test`、`npm pack --dry-run`。使用只读仓库权限，不保存登录态，不上传运行产生的个人文件，不发布包。npm 包白名单不包含 GitHub 工作流配置。

Actions 固定到官方已发布的 [checkout v5.0.0](https://github.com/actions/checkout/releases/tag/v5.0.0) 与 [setup-node v5.0.0](https://github.com/actions/setup-node/releases/tag/v5.0.0) 的完整提交 SHA；这两个版本的 action 运行时与项目测试的 Node 版本是不同概念。推送后应查看实际运行结果，不能以“有 CI 配置”报告“远端已通过”。

## 真实平台复测流程

真实操作需使用者授权，并独立于离线测试进行：

1. 记录系统、Node、Chrome、日期、操作版本与合成化的课程条件；保留私人原始证据在本地。
2. 用户完成登录，打开确切课程与学期；先运行 doctor、status、grading、exam。
3. 只读验证失败时停止写入。核对成绩规则、板块归属与截止要求。
4. 讨论验证只用一条适当的真实回复，离线预览后请用户确认，再提交一次。
5. 记录接口是否返回 replyId；到同一话题人工读回内容与归属。响应中断时先读回，不重新发整批。
6. 视频实验另需明确授权；记录动作、DOM、汇总及其差异，不推断学时或成绩。
7. 将结论写入 [证据说明](../references/verification.md)，标日期、条件、范围、失败和未确认部分。

验证码、风控、阻塞或签名拒绝即停止，不扩展为绕过试验。不要将原始 Cookie、学生信息、成绩、课程链接或 HAR 提交到公开仓库。

## 当前结果的记录方式

验收报告应写实际执行命令、运行版本、通过/失败/未执行和原因。当前重构未包含真实课程复测；历史实测记录只能按历史条件引用。代理行为场景见 [evals/README.md](../evals/README.md)，人工执行结果应另存带日期的记录，不能预填“通过”。
